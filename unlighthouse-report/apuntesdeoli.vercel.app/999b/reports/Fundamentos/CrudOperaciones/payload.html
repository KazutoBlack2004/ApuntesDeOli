Operaciones CRUD

El concepto de
CRUD
define las cuatro operaciones fundamentales para gestionar la persistencia de datos en cualquier aplicación informática. Representa el ciclo de vida básico de la información en un sistema: Crear, Leer, Actualizar y Eliminar.

¿Qué significa CRUD?

CRUD es un acrónimo que resume las acciones necesarias para interactuar con datos guardados de forma permanente (por ejemplo, en un disco duro o en una base de datos). A continuación, se desglosa su significado con la analogía de una biblioteca escolar:

CCreate (Crear)

Añadir nuevos registros al sistema de almacenamiento.
Ejemplo de biblioteca: Registrar un libro nuevo que acaba de comprar la biblioteca para el catálogo.

RRead / Retrieve (Leer / Recuperar)

Consultar la información ya existente para visualizarla o procesarla.
Ejemplo de biblioteca: Buscar un libro en el ordenador para ver en qué estantería está ubicado.

UUpdate (Actualizar)

Modificar los valores de registros existentes que han cambiado o que tenían errores.
Ejemplo de biblioteca: Corregir el nombre del autor de un libro porque estaba mal escrito en el sistema.

DDelete / Destroy (Eliminar)

Remover de forma permanente registros que ya no son necesarios o válidos.
Ejemplo de biblioteca: Dar de baja y borrar del sistema un libro viejo que se ha roto y tirado a la basura.

Anatomía de las Peticiones y Respuestas HTTP

Para profundizar en la simulación, es fundamental entender que cada operación CRUD se comunica mediante una estructura física de red dividida en dos componentes principales: la Petición (Request) y laRespuesta (Response).

1. La Petición HTTP (Cliente → Servidor)

Es el mensaje que el navegador o aplicación móvil envía al servidor solicitando realizar una acción. Se compone de:

  • Método HTTP / Verbo: Indica qué acción queremos hacer (GET, POST, PUT, DELETE).
  • Ruta (Endpoint) / URI: La dirección a la que hacemos la consulta (por ejemplo, /v1/libros).
  • Cabeceras (Headers): Metadatos adicionales que describen la petición (por ejemplo, Content-Type: application/json le indica al servidor que los datos que le enviamos están en formato JSON).
  • Cuerpo (Body): El payload o datos que enviamos para ser guardados. (Los métodos GET y DELETE normalmente no llevan cuerpo, ya que solo solicitan recuperar o borrar algo por su ID en la URL).

2. La Respuesta HTTP (Servidor → Cliente)

Es el mensaje de vuelta enviado por el servidor una vez que ha procesado la petición y guardado/recuperado los datos en la base de datos:

  • Código de Estado (HTTP Status Code): Un número estándar que indica si todo salió bien o si hubo un error. Se dividen en rangos:
    • 2xx (Éxito): Petición correcta. Ejemplos: 200 OK o 201 Created.
    • 4xx (Error del Cliente): Problema del que solicita. Ejemplos: 400 Bad Request (datos erróneos), 404 Not Found (el recurso solicitado no existe) o 401 Unauthorized (requiere autenticación).
    • 5xx (Error del Servidor): Falla interna del propio servidor. Ejemplo: 500 Internal Server Error.
  • Cabeceras de Respuesta: Metadatos del servidor (como tipo de servidor, fecha, tiempo de respuesta o tamaño del archivo).
  • Cuerpo de Respuesta (Body): Los datos resultantes solicitados (usualmente formateados en JSON).

Ejemplos Detallados por Operación

A continuación, se detalla cómo se traduce cada operación en la vida real paso a paso para un recurso de tipo /libros:

1. CREATE (Crear) → POST

El cliente solicita registrar un nuevo libro. Envía los datos correspondientes en el cuerpo (body) de la petición HTTP.

// 1. PETICIÓN HTTP
POST /v1/libros HTTP/1.1
Host: api.biblioteca.com
Content-Type: application/json

{
  "titulo": "Ficciones",
  "autor": "Jorge Luis Borges",
  "categoria": "Cuentos"
}

// 2. OPERACIÓN BASE DE DATOS
INSERT INTO libros (titulo, autor, categoria) VALUES ('Ficciones', 'Jorge Luis Borges', 'Cuentos');

// 3. RESPUESTA HTTP DEL SERVIDOR
HTTP/1.1 201 Created
Content-Type: application/json

{
  "id": 3,
  "titulo": "Ficciones",
  "autor": "Jorge Luis Borges",
  "categoria": "Cuentos"
}

2. READ (Leer) → GET

El cliente solicita consultar un libro por su ID específico (en este caso, el ID 2) pasando el ID en la URL. No requiere cuerpo.

// 1. PETICIÓN HTTP
GET /v1/libros/2 HTTP/1.1
Host: api.biblioteca.com
Accept: application/json

// 2. OPERACIÓN BASE DE DATOS
SELECT * FROM libros WHERE id = 2;

// 3. RESPUESTA HTTP DEL SERVIDOR
HTTP/1.1 200 OK
Content-Type: application/json

{
  "id": 2,
  "titulo": "1984",
  "autor": "George Orwell",
  "categoria": "Distopía"
}

3. UPDATE (Actualizar) → PUT

El cliente solicita modificar los datos del libro con ID 2. Envía todo el nuevo objeto con las correcciones en el cuerpo de la petición.

// 1. PETICIÓN HTTP
PUT /v1/libros/2 HTTP/1.1
Host: api.biblioteca.com
Content-Type: application/json

{
  "titulo": "1984 (Edición Especial)",
  "autor": "George Orwell",
  "categoria": "Ciencia Ficción"
}

// 2. OPERACIÓN BASE DE DATOS
UPDATE libros SET titulo = '1984 (Edición Especial)', categoria = 'Ciencia Ficción' WHERE id = 2;

// 3. RESPUESTA HTTP DEL SERVIDOR
HTTP/1.1 200 OK
Content-Type: application/json

{
  "id": 2,
  "titulo": "1984 (Edición Especial)",
  "autor": "George Orwell",
  "categoria": "Ciencia Ficción"
}

4. DELETE (Eliminar) → DELETE

El cliente solicita borrar el libro con ID 1. Pasa el ID del libro en la URL de la petición. No requiere cuerpo.

// 1. PETICIÓN HTTP
DELETE /v1/libros/1 HTTP/1.1
Host: api.biblioteca.com

// 2. OPERACIÓN BASE DE DATOS
DELETE FROM libros WHERE id = 1;

// 3. RESPUESTA HTTP DEL SERVIDOR
HTTP/1.1 200 OK
Content-Type: application/json

{
  "mensaje": "Libro eliminado correctamente",
  "id": 1
}
